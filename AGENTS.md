# Инструкции автономному разработчику Canvas Assist

**Обязательно сначала прочитать:** `Canvas_Assist_Full_Spec_v1.md`. Этот файл не заменяет спецификацию.

## Не обсуждать с владельцем промежуточные клики

Самостоятельно провести исследование API, создать код, тестовый Vault, запустить автотесты, исследовать скриншоты и логи, исправить дефекты, собрать релиз. Для испытаний использовать только `fixtures/test-vault/` или автоматически созданные синтетические копии. **Никогда не модифицировать настоящий Vault без отдельного прямого разрешения.**

## Порядок задач

1. Составить `docs/verified-integrations.md`: официальные источники, версии и степень подтверждения. TTG 2014 API и живой Canvas API не считать доказанными заранее.
2. Скопировать структуру сборки из `obsidianmd/obsidian-sample-plugin`, закрепить версии зависимостей, настроить strict TypeScript, ESLint, Vitest, CI.
3. Реализовать чистую доменную модель: adventure isolation, party, character, encounter, effects, event clock, Undo/Redo; покрыть unit-тестами.
4. Реализовать API Obsidian, безопасные `.md` / `.canvas` / state JSON операции, импорт с предпросмотром.
5. Реализовать компактный UI, регистрацию команд, CanvasAdapter с fallback, внешние TTG ссылки и offline fallback.
6. Запускать real-app E2E на **изолированном** Obsidian Vault через desktop automation. Mocks не заменяют этот gate.
7. Проверить все AC-01–45 из спецификации, бюджет CPU/RAM/сборки, миграции, corruption recovery, переименование папок, разные приключения с одинаковыми именами.
8. Сделать релиз и полный объективный отчёт. Никакого слова «всё протестировано» при наличии BLOCKED/NOT_RUN critical E2E.

## Абсолютные ограничения

- Без отдельного сервера, SQL, React/Vue/Svelte, фонового polling; не сканировать весь Vault на каждое действие.
- Leaflet — только отдельные географические карты пользователя, **никакой боевой карты**.
- Физические кубики. Dice Roller необязателен.
- Импорт **JSON**, встроенное OCR запрещено.
- У игроков есть папка `Elements/Персонажи`, у NPC — `Elements/NPC`, всё под корнем приключения. Несколько Canvas разделяют одно состояние приключения. Не добавлять дублирующие новые папки.
- Пользовательские Markdown-секции не изменять при импорте. Действия с HP, ресурсами, инициативой сохранять корректно.
- TTG — предпочтительный русский справочник, но права и реальные endpoints проверяются отдельно. Тексты переводов не публиковать без прав.
- У одинаковых монстров отдельная инициатива по умолчанию, общая — только по выбору.
- Таймеры состояний основаны на **игровых событиях**; нет фонового ежесекундного тика.
