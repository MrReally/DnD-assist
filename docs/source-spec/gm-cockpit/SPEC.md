# SPEC — GM Cockpit v2 (плагин Obsidian)

Источник: дизайн-ревизия v2.0 «Brass Atlas». Здесь только v2; решения v1, не вошедшие сюда (отдельный экран Canvas, стол предметов, учёт осмотра, история владения), не реализуются.

## 1. Рабочее пространство

Всё в одном окне Obsidian. Основа — штатный Canvas на файле приключения (`*.canvas`). Плагин добавляет слои вокруг него.

```
┌ вкладки Obsidian ────────────────────────────────────────────┐
│ ленты │  CANVAS (штатный)                         │ GM Panel │
│       │  [NavChip]                                │ 340–420  │
│       │  [InitiativeStrip — только в бою]         │ рельс 40 │
│       │  [PartyDock]                              │          │
└ строка состояния Obsidian ───────────────────────────────────┘
```

Бюджет места (минус вкладки 34 и строка состояния 24):

| Экран | Лента | GM Panel (полная карточка) | Canvas, ширина | Canvas, высота |
|---|---|---|---|---|
| 1280×800 | 44 | 340 (480) | 896 (756) | 742 |
| 1440×900 | 44 | 380 (520) | 1016 (876) | 842 |
| 1920×1080 | 44 | 420 (560) | 1456 (1316) | 1022 |

Если открыты боковые панели Obsidian, Canvas уменьшается ещё; GM Panel сворачивается в рельс 40 px одной кнопкой.

## 2. Canvas

- Один постоянный Canvas на приключение. Никаких отдельных холстов на локации. Карта местности не открыта постоянно.
- Пользователь свободно двигает/создаёт/группирует карточки, проводит связи. Изменения сохраняются постоянно (штатно).
- **NavChip** (слева сверху): назад к предыдущей области · выпадающий список точек обзора · «Перейти» (⌘⇧G).
- **Перейти**: поиск по объектам Canvas и справочнику. Две группы результатов: «На Canvas» (переход) и «В справочнике, не на Canvas» (кнопки «В панель» и «На Canvas»). На холст добавляется только вторым действием.
- **Точки обзора**: сохраняют положение и масштаб, новых Canvas не создают; горячие клавиши 1–9.
- **Контрольные точки**: компактный диалог — создать с названием, список (время, число карточек), «Восстановить». Восстанавливает расположение и состав карточек; HP, инвентарь и ресурсы **не затрагивает**.
- Миникарта-«обзор» в углу — по желанию, не обязательна.

## 3. Взаимодействие Canvas ↔ GM Panel

- Клик по карточке Canvas — выделение (штатное).
- Открытие в GM Panel: двойной клик (ПРОВЕРИТЬ, см. §8), запасные пути — контекстное меню «Открыть в GM Cockpit» и горячая клавиша ⌘⇧O на выбранном узле. Поведение мыши переопределяется в настройках.
- Исходная Markdown-заметка открывается отдельной командой.
- При смене карточки в панели Canvas остаётся в той же области (не двигается).

## 4. GM Panel

Закреплена справа. Ширина регулируется (потянуть край), 340/380/420 по умолчанию; сворачивается в рельс 40 px.

Структура сверху вниз: заголовок (название, индикатор света, поиск ⌘K, свернуть) → закреплённая карточка (если есть) → основная карточка → футер («Начать/Закончить бой», автосохранение, Undo/Redo).

- **Закрепление**: одна дополнительная закреплённая карточка в виде мини-блока (иконка, название, 1 строка, действие вроде «Свет»). Открепление — крестик. Не оконный менеджер. Плавающее размещение — позже, не в этой версии.
- **Типы карточек**: персонаж (PC), NPC, монстр, предмет, оружие, заклинание, помещение, справочная.
- **Компактная / полная** карточка: переключатель в самой карточке; полная панель шире на ~140 px и временно уменьшает Canvas.

### Компактная карточка персонажа/NPC/монстра
Портрет (токен), имя, роль/раса, КД, HP (полоса + число + ввод ±), 3–6 характеристик, атаки с бонусом и уроном (клик → карточка оружия), активные состояния, кнопки «Инвентарь» / «Заклинания», для PC — ячейки и «Отдых».

### Полная карточка
Все характеристики, спасброски, навыки, владения, способности, инвентарь, ресурсы, заклинания, дополнительная информация, отношения. Вкладки или сворачиваемые блоки.

### Правила данных
Бумажный лист игрока — источник истины: любое значение правится вручную. Создание персонажа: основной режим — по правилам 2014 с последующей сверкой; альтернативный — быстрое заполнение с бумажного листа. Официальные источники и простые homebrew-материалы (конструктор homebrew не нужен).

## 5. Бой

- **Старт**: кнопка «Начать бой» в футере панели. Участники — через поиск ⌘K (никакой постоянной панели добавления).
- **Инициатива**: игроки бросают физически — мастер вводит; для NPC приложение бросает автоматически; всё редактируется. Режим «общая / индивидуальная» для одинаковых существ. Одинаковые монстры добавляются группой, но состояние у каждого своё.
- **InitiativeStrip** (по умолчанию): горизонтальная полоса над Canvas — раунд, карточки участников 136 px (инициатива, имя, HP-полоса, число HP, КД, значимые состояния), активный ход выделен (.act), «След. ход» (N), «Развернуть». Прокручивается; для 12+ участников предлагать развёрнутый трекер.
- **Развёрнутый трекер**: оверлей поверх Canvas слева, ширина min(780, 100% − 24). Строка участника: поле инициативы, токен, имя, состояния, HP, поле ±HP, КД, меню. Футер: «Бросить за NPC», «Журнал изменений…», «Закончить бой». GM Panel остаётся доступной. Кнопка «К Canvas» закрывает оверлей.
- **Группа** (мини-плотность): группа сворачивается в одну строку; мульти-выбор → одно число каждому выбранному (это решение мастера, не авторасчёт).
- Выбор участника → его карточка в GM Panel.
- **Не делать**: проверку попадания, автоприменение сопротивлений/уязвимостей, автосписание урона, постоянную панель истории. История изменений и Undo/Redo — по запросу.
- Состояния и эффекты с длительностью, концентрация — отметками, без автоматических ограничений.

## 6. Предметы, помещения, заклинания, отдых, свет

- **Инвентарь**: список (иконка, название, цена, вес, количество, «в руке/надет»), контейнеры раскрываются, монеты, «Передать…» (выбор предмета → персонаж) и «Количество». Карточка оружия: цена, вес, бонус атаки, формула урона, свойства; «Как считается» раскрывает расчёт (ЛОВ + мастерство и т. д.). Тип предмета (библиотека) и состояние экземпляра хранить раздельно. **Нет**: стола, истории владения, временных положений.
- **Помещение**: справочная карточка — описание, объекты, контейнеры и их содержимое, скрытые находки с условиями и СЛ, важные детали. Блоки сворачиваются (`details`). Скрытое помечено штриховкой + иконкой «скрыто» + текстом. **Нет**: «осмотрено/найдено/изъято», счётчиков, прогресса, истории.
- **Заклинание**: карточка-пергамент в панели — уровень, школа, время, дальность, компоненты, длительность, концентрация, эффект, масштабирование, источник; выбор ячейки (3 ур. · осталось N), «Использовать»; кнопка «Свет ▶»; опция автозапуска света для конкретного заклинания (по умолчанию выкл).
- **Импорт TTG Club** (`5e14.ttg.club`): вставка ссылки → распознавание → проверка локальной базы → предпросмотр → «Сохранить и добавить». Ошибка — неблокирующая, с ручным вводом. Сохранённые карточки работают офлайн.
- **Отдых**: компактный диалог с предпросмотром (HP, ячейки, способности, кости хитов, ресурсы класса, эффекты); каждую строку можно править; применяется как **одна** отменяемая операция; правила по классам 2014 — таблица данных.
- **Lightkey** (OSC): cue привязываются к заклинаниям вручную; запуск кнопкой; индикатор соединения (точка) в панели; подробные настройки — в окне настроек плагина. Состояния: подключено / проверка / нет подключения (игра не блокируется).

## 7. Дизайн-система (Brass Atlas)

Файл `styles/gm.css`. Не менять без причины.

Цвета (роль): bg0 `#120f0c` холст · bg1 `#1a1612` панель · bg2 `#221d17` карточка · bg3 `#2b251d` hover · bg4 `#352d23` active · text `#ece2cb` · text2 `#bcb097` · text3 `#968b76` · brass `#c9a45c` выбор/акцент · brass2 `#8f7541` линии · hp `#b34a3f` · ok `#86b07a` · arcane `#9a94ec` магия/концентрация · warn `#e0a94a` секрет/состояния · parchment `#e8dec6` только карточки заклинаний.
Типографика: Cormorant Garamond 600/700 (заголовки, имена), Inter 400/500/600 (всё остальное, числа tabular). Радиусы 4/8/12, шаг 4 px.
Токен существа различается формой: PC — круг, NPC — «капля», монстр — скруглённый квадрат.
Состояния компонентов: default · hover · active · focus (контур arcane 2 px) · disabled · error. Анимации ≤ 400 мс, поддержка reduced-motion.

Новые компоненты v2 (см. `reference/`): GM Panel, PinnedCard, InitiativeStrip, PartyDock, CanvasNode, NavChip, ViewPoints, CheckpointDialog, Disclosure.

## 8. ПРОВЕРИТЬ в Obsidian (не принимать как реализуемое)

| # | Что | Запасной путь |
|---|---|---|
| 1 | Перехват двойного клика по узлу Canvas | контекстное меню «Открыть в GM Cockpit» + ⌘⇧O на выбранном узле |
| 2 | Стилизация узлов Canvas (рамка выбора, иконки типа) | CSS-сниппет; при ограничениях — оставить штатный вид |
| 3 | Оверлеи (InitiativeStrip, PartyDock, NavChip) поверх области Canvas | боковая или нижняя панель Obsidian |

| 5 | Контрольные точки: сохранение и восстановление раскладки без затрагивания игровых данных | вынести игровые данные из `.canvas` в отдельное хранилище, чтобы откат холста их не менял |
| 6 | Определение выбранного узла и связь узла ↔ заметка/карточка | поле frontmatter в заметке узла |
| 7 | Изменение ширины GM Panel и закрепление | фиксированные ширины 340/380/420 |

## 9. Предлагаемый порядок работ

1. Спайки §8 (1–2 дня): подтвердить/отклонить пункты 1, 3, 4, 6.
2. Скелет: manifest, GM Panel как view, настройки, подключение `styles/gm.css`.
3. Карточки: NPC/PC/монстр (компакт) → оружие → заклинание → помещение.
4. Выбор узла Canvas → GM Panel (с запасными путями).
5. Универсальный поиск и «Перейти».
6. Бой: полоса инициативы → развёрнутый трекер → группы.
7. Ресурсы: ячейки, отдых-диалог, Undo/Redo.
8. Импорт TTG Club + офлайн-кэш; Lightkey (OSC).
9. Точки обзора и контрольные точки.
10. Проверка 1280×800.

## 10. Критерии приёмки
1. Canvas не закрывает нужные показатели при 1280×800.
2. Характеристики NPC открываются без смены раздела.
3. Бой начинается без перестройки экрана.
4. Цена кинжала, бонус атаки и урон видны за один клик.
5. Заклинание → эффект → запуск света — в одной панели.
6. Мастеру не требуется регистрировать то, что он помнит сам.
7. Стиль Brass Atlas сохранён.
