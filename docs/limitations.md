# Известные ограничения и открытые вопросы

Severity по §14.1. Открытых дефектов **S1** (порча данных, смешение приключений, утечка) и **S2** (неверные HP/таймеры, потеря подтверждённых записей) нет.

## Не проверено (честные статусы)

| Область | Статус | Почему / что сделано |
|---|---|---|
| Мобильный Obsidian (iOS/Android) | **NOT_RUN** | В окружении нет эмулятора с Obsidian. Сделано: `isDesktopOnly: false`, бандл без Node/Electron (`scripts/check-bundle.mjs`), увеличенные зоны нажатия при `pointer: coarse`, нет действий «только по наведению». | Эталонное железо (MacBook Air M1) | **NOT_RUN** | Производительность измерена на Linux CI-машине; методика и цифры в `docs/test-report.md`. |
| Obsidian < 1.14.4 | **NOT_RUN** | `minAppVersion` 1.7.2 выбран по используемому API; проверена только 1.14.4. |

## Ограничения функциональности (S3/S4, осознанные)

- **Живой Canvas API недокументирован.** Выделение и центрирование узла проверены на 1.14.4; при изменении API включается запасной путь (открыть заметку / подсветить результат), Canvas не ломается. — S3 при обновлении Obsidian.
- **Запись в Canvas не реализована** (в том числе «создать карточку боя на Canvas»): плагин только читает `.canvas`.
- **Obsidian сам переформатирует `.canvas` при открытии** (добавляет `fromSide/toSide`, меняет отступы). Это поведение Obsidian, а не плагина; неизвестные поля и узлы сохраняются.
- **Онлайн-поиск TTG — эксперимент** через недокументированный endpoint сайта 5e14, выключен по умолчанию. Тексты статблоков в плагине не показываются — открывается страница TTG в браузере.
- **«Предыдущий ход»** хранит последние 20 ходов; дальше — общий Undo (100 действий / 256 КиБ).
- **Undo импорта**: состояние откатывается полностью; служебный блок Markdown восстанавливается, только если вы его не меняли после импорта. Созданные файлы не удаляются автоматически, добавленный `canvasAssistId` во frontmatter остаётся. Redo импорта не переписывает Markdown (повторите импорт).
- **Один активный бой на приключение.** Параллельные бои — не в первой версии.
- **Конфликт версий** решается вручную (взять с диска / оставить свою); автоматического слияния боёв нет (как в ТЗ).
- **Концентрация, истощение, болезни** — без автоматики правил: мастер ставит/снимает сам.
- **Связи** показывают исходящие ссылки и ссылки из свойств заметки; обратные ссылки не ищутся (нет сканирования всего хранилища).
- **Игровое время** двигается вручную; интеграции с Calendarium нет.
- **Отдых 2014**: хиты, ячейки, половина костей хитов, спасброски от смерти, счётчики с правилом «короткий/долгий». Классовые особенности не рассчитываются; истощение −1 только по галочке.
- **Узкая панель Canvas** (< ~500 px, например при открытых боковых панелях): строка и лента занимают заметную часть холста — сверните их кнопкой ⚔ или навигатор кнопкой 🔍.
- **Горячие клавиши** работают в основном окне; во всплывающих окнах (popout) используйте команды Obsidian.
- **Размер `main.js` ≈ 199 КБ** — близко к ориентиру 200 КиБ; запас небольшой.
- **`npm audit`**: 3 предупреждения уровня moderate только в инструментах линтинга (`eslint-plugin-obsidianmd` → `obsidian@1.8.7` → `moment`). В `main.js` не попадают: у плагина 0 runtime-зависимостей (`npm audit --omit=dev` → 0).

## Наблюдения о среде (не дефекты плагина)

- После ответа на диалог «Доверяете автору хранилища?» Obsidian 1.14.4 в той же сессии не открывает модальные окна (даже палитру команд) до перезапуска. E2E-раннер перезапускает приложение один раз.
- Playwright `_electron.launch` несовместим с бинарником Obsidian; используется подключение по CDP.


## GM Cockpit 1.2.0: известные ограничения

- Внутренний API Canvas (`selection`, `setViewport`, `createFileNode`, классы `.canvas-node`/`is-focused`) проверен на Obsidian 1.14.4 и 1.7.7 (Linux); при отсутствии возможности отключается она одна (двойной клик → команда/меню, точки обзора, добавление на Canvas → открытие заметки). Это проверено E2E «X» подменой API.
- Восстановление контрольной точки — единственная запись плагина в `.canvas`, только по подтверждению и после защитной копии. «Добавить на Canvas» создаёт узел средствами самого Canvas.
- **SRD 5.1 — это не весь Player's Handbook.** Нет: предысторий кроме Acolyte (например, Criminal — вводится вручную, навыки берутся с листа), подклассов кроме одного на класс, черт кроме Grappler, заклинаний и существ вне SRD, Xanathar's/Tasha's и т. д. Такой контент — только пользовательский ввод/JSON.
- Извлечение из PDF: статблок Giant Fly (нет строки Challenge) и таблица уровней Ranger получены не полностью (помечены `partial`/предупреждением в `meta.warnings`); таблицы Bard/Sorcerer/Monk читаются, но их «колонки» не интерпретируются, ресурсы по ним заданы формулами, проверенными по тексту SRD. Атаки существ разобраны только в формате «Melee/Ranged Weapon/Spell Attack … Hit: N (dice) type damage»; особенности и действия хранятся текстом SRD без разбора.
- Перевод: SRD доступен только на английском. Русские названия оружия/доспехов/снаряжения — общепринятая терминология для отображения (не SRD, не проверена); существа, заклинания и черты показываются по-английски. Поиск по русским ключевым словам («гоблин», «бандит» …) — вспомогательный.
- TTG Club: автоматической загрузки нет (robots.txt запрещает `/api`, условия запрещают автосбор). Ссылка разбирается и ищется в локальной библиотеке; иначе — JSON или ручной ввод.
- Lightkey: проверен локальным UDP-приёмником; реальный Lightkey, порт по умолчанию (21600) и глаголы `deactivate`/аргументы не подтверждены.
- Классовые способности, кроме перечисленных ресурсов, не автоматизированы (описания — в тексте SRD). Автоматически не выбираются: заклинания, повышения характеристик, подкласс, навыки, магическое восстановление — решения игрока.
- Нет рельса 40 px, плавающей панели, закреплённой второй карточки, мультиклассирования в конструкторе (поля листа правятся вручную).
- Мобильные устройства, macOS и Windows не проверялись (macOS: `scripts/mac-smoke.sh` готов к запуску на Mac).
