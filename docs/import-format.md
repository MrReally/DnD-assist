# Формат импорта персонажа (JSON, schemaVersion 1)

Машинная схема: [`schemas/character-import.schema.json`](../schemas/character-import.schema.json). Принимается один объект, массив объектов или `{ "characters": [ ... ] }` (до 200 записей). OCR и распознавание фото в плагине нет: JSON готовите вы или внешний ИИ по бумажному листу.

## Правила

- Обязательны только `schemaVersion: 1`, `kind: "player-character"`, `name`.
- **Неизвестное не заполняйте.** Пустое поле остаётся пустым («—»), плагин ничего не угадывает и не ставит 0.
- Неизвестные поля, неверные типы, отрицательные значения, `текущее > максимум`, переполнение чисел, неизвестная версия схемы → ошибка с путём поля (`$.hitPoints.current: …`); такая запись не импортируется.
- HTML/скрипты в строках не исполняются: текст экранируется при записи в Markdown, есть предупреждение.
- `characterId` (латиница, цифры, `.`, `_`, `-`) — стабильный ID для повторного импорта. Без него ID создаётся автоматически и записывается во frontmatter как `canvasAssistId`.
- Машинные id навыков — английские (`arcana`, `history`, `sleight_of_hand`…); на листе показываются русские названия.
- `customResources`: `{ "id", "name", "current", "max", "recovery": "manual" | "short" | "long" }`. Без `recovery` — `manual`: такой счётчик на отдыхе сам не восстанавливается.

## Пример

```json
{
  "schemaVersion": 1,
  "kind": "player-character",
  "characterId": "pc-mira",
  "name": "Мира",
  "class": [{ "name": "Волшебник", "level": 3 }],
  "species": "Полуэльф",
  "background": "Мудрец",
  "abilityScores": { "str": 8, "dex": 14, "con": 12, "int": 16, "wis": 10, "cha": 13 },
  "proficiencyBonus": 2,
  "armorClass": 12,
  "initiativeModifier": 2,
  "speedFeet": 30,
  "hitPoints": { "max": 20, "current": 9, "temporary": 0 },
  "hitDice": [{ "die": "d6", "total": 3, "remaining": 2 }],
  "spellSlots": { "1": { "max": 4, "current": 2 }, "2": { "max": 2, "current": 2 } },
  "savingThrowProficiencies": ["int", "wis"],
  "skillProficiencies": ["arcana", "history"],
  "attacks": [{ "name": "Кинжал", "bonus": "+4", "damage": "1к4+2 колющий" }],
  "spells": [{ "name": "Волшебная стрела", "level": 1 }],
  "features": [{ "name": "Магическое восстановление" }],
  "inventory": [{ "name": "Книга заклинаний" }],
  "customResources": [{ "id": "arcane-recovery", "name": "Магическое восстановление", "current": 1, "max": 1, "recovery": "long" }],
  "notes": "Поля, которых нет на бумажном листе, оставлены пустыми."
}
```

## Что происходит при импорте

1. **Предпросмотр**: ошибки/предупреждения, куда будет записан лист (`Elements/Персонажи/<Имя>.md`), действие (создать / обновить / пропустить) и diff.
2. **Создание**: новая заметка с frontmatter `canvasAssistId`, заголовком и служебным блоком `<!-- canvas-assist:begin -->…<!-- canvas-assist:end -->`, плюс раздел «Заметки мастера» для ваших записей.
3. **Повторный импорт** (по `characterId` или по `canvasAssistId` заметки): обновляются постоянные значения и служебный блок. Текущие хиты, ячейки, кости хитов и счётчики **сохраняются**, если не включено «Перезаписать текущие значения». Повышение максимума текущее значение не трогает; понижение — ограничивает им.
4. **Совпадение только по имени файла** не считается тем же персонажем: по умолчанию «пропустить», явно можно «обновить эту заметку» или «создать новую» (`Мира 2.md`).
5. Всё вне служебного блока остаётся байт-в-байт как было.

## Подсказка для внешнего ИИ

> Перепиши данные с фото листа персонажа D&D 5e (2014) в JSON по схеме Canvas Assist v1 (пример выше). Не придумывай значения: если поля нет или оно нечитаемо — не включай его. Числа — целые. Навыки — английскими id (arcana, history, …).
