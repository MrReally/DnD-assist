## Ограничения и выводы

1. **Всё, кроме S5 и S7(сохр.), опирается на недокументированный внутренний API Canvas** (`canvas.selection`, `node.file`, `setViewport`, `.canvas-node`, класс `is-focused`). Изоляция — только в `src/adapters/canvas-adapter.ts` с пробой возможностей при каждом вызове. Версия Obsidian ≠ 1.14.4 не проверялась.
2. **S1.** Двойной клик перехватывается только пока работает DOM-класс `.canvas-node`. Чтобы не ломать правку текстовых узлов, перехват включён **только** для файловых узлов, связанных с карточкой (персонаж/NPC), остальные идут штатным путём. Запасные пути (команда, контекстное меню, хоткей) обязательны и реализуются вместе.
3. **S5.** Восстановление — единственная запись плагина в `.canvas`: только по явной команде, после защитной копии. Инвариант AC-38 («плагин не пишет в `.canvas`») уточняется: «кроме явного восстановления контрольной точки».
4. **S3.** В тесте открыт левый сайдбар (344 px), Canvas = 936×760; при открытом правом сайдбаре ширина меньше. Бюджет §1 SPEC (Canvas ≥ 896 при панели 340) выполняется только при свёрнутой левой панели — на 1280×800 мастеру нужно закрывать левый сайдбар.
5. **S7.** Рельс 40 px не проверялся: штатное сворачивание = 0 px.
6. Не проверялись: macOS/Windows, другие версии Obsidian, конфликты со сторонними плагинами Canvas, производительность Canvas на 500+ узлах (перф-бюджет v1 есть для домена и индекса).
